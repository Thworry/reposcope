# Governance

RepoScope currently uses a maintainer-led governance model. The repository owner is the final decision-maker for releases, security disclosures, ruleset versions, roadmap scope, and contributor access.

## Decision principles

Decisions prioritize:

1. an honest, reproducible public contract;
2. the privacy and security boundaries documented in the repository;
3. bilingual semantic parity and accessibility;
4. deterministic tests and maintainable implementation; and
5. compatibility with static GitHub Pages hosting and bounded browser resources.

Normal fixes and documentation improvements proceed through pull-request review. Changes to score meaning, ruleset version, fixed network origins, persistence, credentials, backend services, or execution behavior require an explicit design discussion and updated methodology, architecture, tests, and bilingual documentation before merge.

## Releases

The maintainer publishes versioned releases after local and hosted quality gates pass. A release does not imply that RepoScope or an inspected repository is free of defects or vulnerabilities.

## Evolution

If sustained contributor activity makes shared governance useful, this document may be revised through a public proposal that defines maintainer nomination, decision rights, conflict handling, and transition safeguards.
