# Chinese Localization Design

Date: 2026-08-24
Status: Approved under the user's standing default-execution authorization

## Goal

RepoScope 的中文界面和项目报告应该像中文编辑直接写成的内容，而不是英文界面的逐句翻译。读者打开报告后，应能快速回答这些问题：项目是做什么的，适合什么场景，大体如何实现，怎样安装和继续开发，是否值得信任，以及还在不在维护。

本次改动只优化 RepoScope 自己写的中文。README 引用、项目名称、代码、命令、路径、版本号和仓库中的其他原文必须保持不变，也不能因为润色而增加原文没有的事实。

## Product decision

采用“人工编写的中文文案 + 明确的生成语言约束”，不增加运行时翻译层。

- 静态报告继续使用现有 `zh-CN` 消息表，直接改写标题、说明、空状态、风险提示和方法说明。
- 专家简报继续由现有模型流程生成，但提示词要求使用自然的中国大陆简体中文，避免照搬英文语序。
- 保留中文技术读者熟悉的 GitHub 和开发术语，例如 README、Star、Watch、Fork、Issue、PR、API、CLI、RAG 和 TypeScript。不要为了“全中文”改成生僻或不常用的译法。
- 证据边界、安全约束、报告结构、字段和数据计算保持不变。

## Alternatives considered

### 直接改写现有中文消息并加强生成提示词，选用

改动集中、风险可控，也能同时改善静态报告与专家简报。现有双语键值契约、组件结构和测试工具都可以复用。

### 把中文文案拆成新的独立模块

单独文件更便于未来交给编辑维护，但本次并不需要改变消息加载方式。现在拆分会产生大量无关 diff，也不会直接改善中文质量。

### 在浏览器里调用模型实时润色

这种方式会让同一仓库每次出现不同说法，还会增加成本、等待时间和隐私边界。它不适合承担基础界面和确定性报告的本土化。

## Language principles

### 先说人话，再说证据边界

标题直接对应读者的问题。例如使用“先看结论”“这个项目适合做什么”“项目还在维护吗”，少用“证据状态”“项目适用性注意事项”“观察到的维护证据”这类抽象名词组合。

风险说明保留，但放在具体结论之后，用一句话说明边界。不要在相邻段落里重复“无法确认”“不代表”“仍需核实”。

### 使用中文常见语序

- 多用短句和主动句，避免把多个名词和修饰语堆在一起。
- 少用分号、破折号和翻译腔连接词。
- 同一段中不要连续以“README”“仓库”“公开证据”开头。
- 数字和事实用标签呈现，解释文字负责告诉读者这些数字意味着什么。
- 空状态说明“没找到什么”和“读者下一步能做什么”，但不得给出未经仓库记录的命令。

### 技术词按中文社区习惯保留

README、Star、Watch、Fork、Issue 和 PR 保留英文写法。用户已经熟悉的 API、CLI、GitHub Copilot、TypeScript 等名称不强行翻译。普通概念优先中文，例如把 onboarding 写成“上手”，把 repository 在面向用户的叙述里写成“项目”或“仓库”，按语境选择。

### 原文与解读分开

仓库原文继续按原语言显示，并保留固定提交来源。RepoScope 可以解释原文对采用决策意味着什么，但不得改写引文、替项目补充承诺，也不得把文档声明写成已验证事实。

## Scope

### Primary reader path

改写落地页、分析进度、报告头部、目录、README 解读、决策摘要、适用场景、可靠性、架构、安装运行、安全隐私、维护状态和替代方案中的中文。

社区数据统一使用 `Star`、`Watch`、`Fork` 和“未关闭的 Issue 和 PR”。许可证状态使用“有许可证信息”“未找到许可证信息”“暂时无法确认”，避免“发现证据”这类机器式标签。

摘要不能继续套用英文固定句式。工作流、架构和使用边界按实际存在的字段动态组句，缺少某项时直接省略，不显示“0 个步骤”“0 个目录”，也不把“无法确认”塞进并列名词中。四项摘要末尾只保留一条统一的说明，避免每张卡重复强调“不是验证”。

组件中硬编码的半角冒号、破折号和空值符号改为本地化整句。可访问名称、信号状态、替代项目搜索和方法权重都通过消息模板生成。专家证据来源在中文界面按证据种类和路径显示中文名称，不直接暴露服务端英文标签。

### Expert briefing

改写专家模式的授权说明、进度、章节标题、空状态和结论标签。中文生成提示词新增以下要求：

1. 使用自然的中国大陆简体中文，不逐句翻译英文结构；
2. 优先使用常用词、短句和主动句；
3. 保留通用技术术语、项目名、标识符、命令和原文；
4. 避免名词堆叠、官样表达、营销语和重复免责声明；
5. 所有事实仍必须来自允许的证据，未知项继续遵守既有固定前缀和单句规则。

提示词版本从 `1.0.0` 升到 `1.1.0`，使旧缓存不会继续展示改写前的中文。

### Technical appendix and public docs

技术附录仍保持准确和紧凑，只处理明显的直译和不自然标签，不改变评分、规则或推荐阈值。中文 README 与方法文档同步说明“中文原生表达”和原文保留边界。

## Testing

- 消息契约继续保证英文和中文键完全一致。
- 为核心中文阅读路径冻结一组代表性标题和说明，防止回退到旧翻译腔。
- 扫描 RepoScope 自写的中文消息，禁止使用破折号，并检查 Star、Watch、Fork、Issue、PR 的统一写法。
- 专家提示词测试确认 `zh-CN` 包含自然中文约束，同时保留未知项固定前缀和安全边界。
- 组件测试更新可访问名称和关键文本断言。
- 运行完整单元测试、服务器测试、类型检查、格式检查、构建和浏览器端到端测试。
- 用真实公开仓库在中文界面验收桌面与移动端，确认原始 README 引文没有被修改，页面没有溢出或控制台错误。

## Non-goals

- 不翻译或改写仓库原文。
- 不系统性重写英文界面；为了修复零值拼句和硬编码标点，可以共享调整组合逻辑。
- 不增加新的翻译依赖或模型调用。
- 不调整评分、分析算法、报告结构和数据来源。
- 不以“更像人写的”为理由添加仓库没有提供的判断或事实。
