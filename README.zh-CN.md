# RepoScope 项目透视

[English](README.md)

RepoScope 帮你在投入时间之前，先看懂一个陌生的公开 GitHub 仓库。它从 README 开始，把项目用途、适用场景、整体架构、上手方法、风险、维护情况和替代方案整理成一份便于阅读的报告，并附上信息来源。基础分析直接在浏览器中完成，支持中文和英文。如果部署者打开了专家模式，你还可以在明确同意后获取更深入的 GitHub Copilot 解读。这部分不会覆盖基础报告。

**在线站点：** <https://thworry.github.io/reposcope/>

RepoScope 只根据仓库中的公开信息帮助你判断，不会替你做最终决定。它不会运行项目、验证功能是否正确、测量运行时测试覆盖率，也不会开展安全审计或查找漏洞。它同样不能证明软件可以安全使用。

## 使用

1. 打开 [RepoScope 在线站点](https://thworry.github.io/reposcope/)。
2. 粘贴一个形如 `https://github.com/owner/repository` 的公开仓库地址。
3. 选择“**开始解读**”。RepoScope 每次只处理一个仓库。
4. 先看“**从 README 开始了解项目**”。如果还需要总分、分析把握度、六个评分维度、优点、改进项、检查范围和规则依据，再打开默认收起的“**技术附录与分析方法**”。
5. 如果站点部署者配置了专家模式，可以选择“**生成深入解读**”，阅读说明并授权 RepoScope GitHub OAuth App。这一步完全可选。跳过或生成失败都不影响默认报告。
6. 使用“**English / 简体中文**”切换界面语言。切换语言不会重新获取仓库数据，也不会重新计算分数。

报告生成后，共享地址中只包含仓库标识。每次重新分析都会发出三个无需认证的只读 GitHub REST 请求，然后在既定限制内读取本次查看的提交中的原始文件。

RepoScope 可以对任何语言的仓库进行通用检查。JavaScript、TypeScript 和 Python 还支持更深入的静态指标。如果受支持的源代码没有达到分析门槛，可读性和复杂度会显示为不可用，整体结果则标记为“**仅通用检查**”和“**初步结果**”。

报告会把“项目自己说能做什么”和“从仓库结构能确认什么”分开说明。项目用途主要取自 GitHub 仓库说明和首选 README，项目类型则根据选定的项目清单文件、GitHub Topics 和仓库目录判断。所有来源链接都固定到本次查看的提交，仓库作者写的内容始终保持原文。RepoScope 的中文界面直接按中文阅读习惯编写，不会在运行时翻译。基础报告不使用 AI，也不是针对个人情况给出的建议，不会猜测你的具体需求，更不会声称某个仓库一定适合你。

请参阅完整的 [规则集 `1.0.0` 方法说明](docs/methodology.md)、[架构与威胁边界](docs/architecture.md)以及[版本历史](CHANGELOG.md)。

## 从 README 开始了解项目

报告分为八个部分。你可以先看项目文档怎么介绍自己，再看仓库中的公开信息能确认什么：

1. **项目是做什么的**：先用仓库说明和 README 介绍项目；
2. **社区热度与维护数据**：列出 Star 数、Watch 数、Fork 数、未关闭的 Issue 和 PR、最近推送时间，以及许可证文件或 GitHub 识别出的许可证信息；
3. **先看重点**：概括主要功能、怎么使用、代码大致怎么组织，以及使用前还要确认什么；
4. **README 里怎么说**：整理 README 中的项目概览、目标读者、待解决问题和使用场景，也保留依赖、限制与成熟度说明；
5. **主要功能**：按 README 原有主题展示最多九组主要功能；
6. **README 给出的使用流程**：按原文顺序列出步骤，没有连接线也能看懂；
7. **README 的说法与仓库情况**：对照 README 中的说法和仓库结构，概括项目类型、技术栈与主要源码目录；
8. **RepoScope 怎么看**：分别说明值得留意的内容、使用前要确认的问题及其实际影响。

GitHub 的 `stargazers_count`、`subscribers_count` 和 `forks_count` 分别提供 Star 数、Watch 数和 Fork 数。`subscribers_count` 是 **Watch 数** 的数据来源。GitHub 的 `open_issues_count` 同时包含 Issue 和 PR。这些数字只能说明公开关注度。流行度不能证明项目质量或安全性。

仓库作者写的内容始终保持原文。切换 RepoScope 的界面语言不会翻译、改写或重新获取这些内容。README 提取和基础分析不使用 AI。找不到首选 README 时，页面会直接说明这部分不可用。如果首选 README 没有成功读取，页面会把解读标为不完整；如使用其他 README 作为有限依据，来源仍会显示真实文件。可选的深入解读会单独标明，也不会修改基础报告中的事实或评分。

README 解读之后，报告按下面七个问题展开。“**是否值得继续了解**”是开头的判断摘要，后面六个正文章节带有来源链接：

1. **是否值得继续了解**；
2. **这个项目适合做什么**；
3. **项目是否靠谱**；
4. **代码大致怎么组织**；
5. **如何安装、运行和二次开发**；
6. **是否存在安全或隐私风险**；
7. **项目还在维护吗**。

这些判断只依据本次检查到的公开信息，不参与评分。它们不能说明项目一定适用、正确、安全、合规或可以放心使用。

仓库文档中的命令只会显示为普通文本，RepoScope 绝不会运行它们。遇到标记为需要复核的命令，请先检查再复制。来源只链接到本次分析的固定提交。GitHub 的替代项目搜索只是寻找候选项目的起点，比较时仍应使用同一套检查方法。“**技术附录与分析方法**”保留评分报告和详细方法，默认收起。打开或关闭它都不会重新获取仓库数据，也不会重新计算报告。

## 可选深入解读

如果部署者配置了专家模式，RepoScope 可以根据选定的公开信息生成一份更深入的简报。系统会分别分析适用场景、上手方式、整体架构、可靠性和生态，再交叉核对缺少依据或表述过头的结论，最后整理成十个带来源链接的章节。这份简报重点讲项目做什么、适合谁、怎样开始、还有哪些未知、安全与隐私注意事项、维护情况以及值得对比的替代方案，不会逐个函数点评代码。

首次使用专家模式前，你必须明确同意，并通过不申请额外权限范围（scope）的 RepoScope GitHub OAuth App 授权。服务会在内存中短期保存你的 GitHub 令牌，并使用你自己的 GitHub Copilot 额度。它不使用 GitHub Models，也没有项目自有的模型密钥。选定的公开 README、文档、清单、仓库目录、发布和活跃度信息，以及替代项目信息会发送给 Copilot 会话。该会话不能使用工具、插件或仓库工作区，也不能执行命令。仓库代码和命令始终只作为文本处理。

除明确标为“尚未确认”的内容外，模型写出的每条判断都必须引用经过检查的来源；未知项不会伪造引用。RepoScope 会拒绝无效引用、虚构的替代方案、写进正文的实时热度数字、危险命令建议，以及没有依据的安全或隐私保证。Star 数、Watch 数、Fork 数、未关闭的 Issue 和 PR、最近推送时间、归档状态和许可证信息会在模型输出通过检查后，由服务端重新获取并加入报告。即使深入解读不完整或生成失败，基础报告仍会保留。

## 报告示例解读

下面用 `https://github.com/Thworry/reposcope` 说明报告应该怎么读。RepoScope 会先确定默认分支当前对应的具体提交，整份报告都以该版本为准。总分汇总适用规则的结果；分析把握度表示仓库目录和可用信息读取、解析得是否完整，它不是第二个质量分数。

六个维度应分别阅读：文档与上手体验、可运行性证据、代码可读性、复杂度与结构、测试与自动化、维护健康度。随后检查范围与失败项，了解文件树截断、跳过文件、获取失败、解析失败、不支持的源代码或触及限制等情况。改进项列表列出适用规则中的失分点，并在有证据时链接到对应文件。

来源链接采用固定提交的 `blob/<commit>/path#Lx-Ly` 形式，因此即使默认分支后来更新，链接仍会指向本次分析的版本。仓库提交或规则集发生变化时，具体分数、分析把握度、发现和链接也可能变化。RepoScope 只把仓库内容当作文本处理，不会执行项目、验证项目行为，也不能证明项目正确、安全或可以放心使用。

## 限制

每次扫描严格限制为：

- 最多选择 200 个文件；对符合读取条件的源码、文档、清单和配置文本，最多发起 200 次原始文件请求；
- 解码文本总量最多 10 MiB；
- 每个符合读取条件的文本文件最多读取 256 KiB，包括源码、文档、清单和配置文本；
- 原始文件请求的并发数最多为六个；
- 每个原始文件的超时时间为 15 秒；
- 整个源文件获取阶段最多为 90 秒。

GitHub 还可能只返回部分仓库目录，或限制未登录请求的频率。报告会明确显示抽样、跳过文件、读取失败、解析失败、不支持的源代码和达到读取上限等情况，并相应降低分析把握度。评分维度或读取范围不同时，不应直接比较分数。

## 隐私

默认的基础分析不需要登录，也不用提供 GitHub 令牌。它不依赖后端、数据库、统计服务、广告或 AI。公开仓库数据只在你的浏览器与 GitHub 之间传输，分析使用当前设备的算力。

仓库源代码始终被视为不可信文本。RepoScope 不会执行、导入、求值或以 HTML 形式渲染它。原始源代码正文和 GitHub 原始响应不会被持久化。经过验证的最终报告和规范化公开元数据可在 `sessionStorage` 中缓存 15 分钟；唯一持久保存的偏好是本地存储中的 `en` 或 `zh-CN`。

可选专家模式会增加 TypeScript 后端、GitHub 授权、GitHub Copilot 处理和受容量与保留期限限制的 SQLite 缓存。OAuth 令牌只会在不透明、`HttpOnly` 的内存会话中保存，最长为空闲八小时，并在退出或服务重启时删除。经过验证的公开信息解读最多缓存 30 天，公开替代方案列表最多缓存 24 小时。原始 README 正文、源代码、模型会话记录、提示词、令牌、实时热度数字和私有仓库都不会被存储。详见[部署与数据流约定](docs/deep-analysis-deployment.md)。

## 安装并在本地运行

使用[在线站点](https://thworry.github.io/reposcope/)无需安装，并且仍然不需要 GitHub 令牌。贡献者的本地环境需要 Node.js 24.x 和 pnpm 11.16.0。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

随后打开 <http://localhost:5173/>。Vite 开发服务器仅供本地使用，不得将它作为公开应用部署。

默认本地构建会关闭专家模式。如需运行可选 API，请创建一个不申请额外权限范围（scope）的 GitHub OAuth App，按 [docs/deep-analysis-deployment.md](docs/deep-analysis-deployment.md) 配置严格的同站环境，并在另一个进程运行 `pnpm server:dev`。不得把 OAuth 密钥或用户 GitHub 令牌放进前端环境变量。

## 开发

运行本地质量检查：

```sh
pnpm lint
pnpm format:check
pnpm test:coverage
pnpm build
pnpm check:bundle
pnpm exec playwright test
pnpm check:lighthouse
```

自动化浏览器测试使用固定的 GitHub 测试数据，不会消耗真实 GitHub API 请求额度。提交修改前请阅读 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 架构

主要代码区域包括：

- `src/features/github`、`repository` 和 `scanner`：负责校验数据，并按固定规则选择文件；
- `src/features/analyzers`、`rules` 和 `worker`：负责在限定范围内完成静态分析与评分；
- `src/features/deep-analysis`：负责可选浏览器客户端、流协议校验和独立 React 状态；
- `src/components`、`i18n` 和 `styles`：负责中英双语报告体验；
- `server/github`、`evidence`、`panel`、`cache` 和 `deep-analysis`：负责授权后的信息获取、不能调用工具的 Copilot 分析、严格校验和限期缓存；
- `e2e` 和就近放置的测试：提供可重复的浏览器和模块验证；
- `.github/workflows`：负责 CI 和 GitHub Pages 部署。

详细数据流、固定端点、缓存策略、CSP 和威胁模型见 [docs/architecture.md](docs/architecture.md)。

## 部署

推送到 `main` 后会运行 CI 和使用固定版本依赖的 GitHub Pages 工作流。未设置 `REPOSCOPE_API_ORIGIN` 时，Pages 产物是通过 `REPOSCOPE_BASE_PATH=/<repository-name>/` 构建的 Vite 静态站点；部署使用 GitHub Actions，不需要运行时密钥。

在本地构建子路径版本：

```sh
REPOSCOPE_BASE_PATH=/reposcope/ pnpm build
pnpm check:bundle
```

专家模式是独立的可选部署：在同站自定义 API 域名上运行仓库提供的非 root 容器，把 SQLite 路径挂载到持久卷，把 OAuth 凭据保存在托管平台的密钥存储中，并把非敏感的 Pages 变量 `REPOSCOPE_API_ORIGIN` 设为该 HTTPS 源。公开启用前必须严格遵循[专家模式部署指南](docs/deep-analysis-deployment.md)并完成人工验收。

不要部署开发服务器；如需增加其他令牌输入、代理、分析端点、模型提供方或远程运行时资源，必须先通过架构、安全、隐私、方法说明和双语文案评审。
